## Outline (skill step 3)

Not confirmed with a user. Decision: use the skill's suggested shape, adapted:

- The **Ticket** gets its own chapter *before* the spine. The spine chapter calls `controller.markDone` and checks
  `ticket.isSettled` on almost every path; explaining that mid-spine would break its flow.
- The **executor** (one attempt) gets its own chapter after the spine, because it is the densest file
  and has its own crux (an attempt must always end).
- Retry *decisions* (policy, backoff, Retry-After, which error the caller sees) are split from the
  spine's retry *flow*, so the spine stays a straight line.
- Subsystems are grouped by question, not by file: "isolation" (bulkhead + semaphore + rate limiter, which all
  queue or delay attempts) and "failing fast" (breaker + retry budget, which both refuse work).
- Observability and the extension points (middleware, Zod, OTel) share one chapter: they are all
  "how information/behaviour crosses the library boundary", and each is small.
- Testing, tooling and release share one "Craft" chapter, with a feature anatomy taken from git (#186, retry budget).
- Open problems is an appendix chapter built from the open `design`/`enhancement` issues plus the bugs found while writing.

Reason for not splitting further: the source is ~4,950 lines; 12 chapters of 1,500–4,000 words cover it
without padding.
